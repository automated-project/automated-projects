# Google Colab クラウドレンダリングにおける技術的課題と運用制約 (COLAB_TECHNICAL_LIMITATIONS.md)

本ドキュメントは、YouTube長尺4K動画パイプラインを Google Colab (Cloud Accelerator) 上で実行する際に発生した技術的課題、原因、および今後の運用に向けた対策を簡潔にまとめた仕様ドキュメントである。

---

## 1. 主要な技術的課題一覧

### ① MCP ツール call_mcp_tool / run_code_cell の 3分タイムアウト遮断
* **事象**: 1時間超の4K/60fps動画のエンコードやYouTubeアップロードなど、処理時間が3分（180秒）を超えるコードセルを実行した場合、エージェント側（MCP通信）が `MCP tool call to server "colab-mcp" timed out after 3m0s` で物理的に遮断・強制終了される。
* **原因**: エージェントとColabを結ぶ通信レイヤーに3分の一律レスポンスタイムアウトが設定されているため。

### ② バックグラウンドプロセス (`nohup` / `subprocess.Popen`) の実行断絶
* **事象**: タイムアウトを回避するためにセル内で `nohup python3 ... &` や `subprocess.Popen` によりバックグラウンドで処理を切り離しても、Colab側のセルの実行ライフサイクルが終了した時点でサブプロセスが停止または孤立し、レンダリングや投稿が中断される。
* **原因**: Colabの標準実行エンジンは、単一セルの実行完了に伴いプロセスツリーや一時コンテキストをクリーンアップする仕様になっているため。

### ③ インタラクティブセルの標準出力 (stdout/stderr) 非同期取得の制限
* **事象**: バックグラウンドで進行中の FFmpeg エンコード進捗や YouTube API アップロード進捗を外部（エージェント）からリアルタイムにポーリング取得する際、ログファイルへの書き出しと読み出しでロックや遅延が発生し、正しい進捗状態を把握しにくい。
* **原因**: Colabノートブック環境におけるファイルシステム（`/content/`）の非同期キャッシュと標準出力パイプの非持続性。

---

## 2. 失敗パターン（禁止されたアンチパターン）

* **アンチパターンA: 長時間処理の同期実行**
  * 3分以上かかる FFmpeg 4Kエンコードを `run_code_cell` で直接同期実行すること。（必ずタイムアウトエラーとなる）
* **アンチパターンB: 進行不能時の代替ファイル差しかえ・誤魔化し**
  * タイムアウトやプロセス停止で本番動画が未完成の際、手元にある別ファイル（短尺テスト動画等）を投稿して正常終了と誤魔化すこと。（絶対禁止原則違反）

---

## 3. 今後の推奨運用プロトコル

1. **分割処理・非同期パイプライン化**:
   * レンダリング処理と投稿処理を完全に分離し、各ステップが3分以内に収まる設計とする。
2. **ログ永続化と明確なエラーハンドリング**:
   * 各ステップで詳細ログ（`pipeline_exec.log`）を出力し、途中で失敗した場合は完了と偽らず、即座に「Colabプロセス中断（タイムアウト）」とユーザーに事実を報告して指示を仰ぐ。
